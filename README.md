# Aditum App (generated)

A governed industrial app generated by the Aditum App Builder. This is a **vetted
template** — real, audited code (React-TS + Vite frontend, FastAPI backend) —
parameterized by the generated `manifest.json` and deploy config. It is not
hand-written or model-authored per app.

## What it does
- **Signs users in with Aditum SSO.** The backend validates the user's Aditum
  login token and gates every data route.
- **Reads live, governed data.** The backend reads through the Aditum query API
  using a scoped, read-only service token — it never holds raw connector
  credentials and can never write.
- **Renders the manifest.** The frontend loads the manifest and renders KPI
  cards, trend charts, and tables from real data. No data is ever fabricated —
  a component with no credentialed data shows an explicit empty state.

## Two credentials, kept separate
| Purpose | Env | Notes |
|---|---|---|
| End-user login | `ADITUM_JWT_SECRET` | Validates the Aditum SSO token (identity only) |
| Data read | `APP_DATA_TOKEN` | Scoped, read-only Aditum service token |

See `.env.example` for the full config. Deploy is handled by the Aditum App
Builder's guided flow (target → your GitHub/Azure → Aditum SSO → scoped token).

## Layout
- `backend/` — FastAPI: `auth.py` (Aditum SSO), `governed.py` (governed read),
  `routes.py` (`/api/config`, `/api/manifest`, `/api/series`).
- `frontend/` — React-TS/Vite: login gate + manifest-driven components.
